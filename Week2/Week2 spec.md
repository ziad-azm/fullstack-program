## API to implement (FastAPI) — full CRUD

| Method   | Path          | Behaviour                                                              |     Success code      |
| -------- | ------------- | ---------------------------------------------------------------------- | :-------------------: |
| `POST`   | `/items`      | **Create** an item; `400` on validation error                          |     `201` / `400`     |
| `GET`    | `/items`      | **Read all** — return every item as a JSON array                       |         `200`         |
| `GET`    | `/items/{id}` | **Read one** — `404` if it doesn't exist                               |     `200` / `404`     |
| `PATCH`  | `/items/{id}` | **Update** an item (partial); `404` if missing, `400` on invalid input | `200` / `404` / `400` |
| `DELETE` | `/items/{id}` | **Delete** an item; `404` if missing                                   |     `204` / `404`     |

### Item shape

```json
{
  "id": 1,
  "name": "Notebook",
  "price": 25.5,
  "in_stock": true,
  "created_at": "2026-08-02T19:00:00Z"
}
```

### Request body for POST /items

```json
{ "name": "Notebook", "price": 25.5, "in_stock": true }
```

- `id` and `created_at` are generated by the server, never sent by the client.
- `in_stock` is optional and defaults to `true`.

## Requirements

1. **Routing** — use FastAPI path operation decorators (`@app.get`, `@app.post`).

2. **Models / schemas** — use Pydantic `BaseModel`:
   - `ItemIn` (create input): `name`, `price`, optional `in_stock`
   - `ItemUpdate` (update input): all fields **optional** so PATCH can update only what's sent (use `exclude_unset=True` when applying the update)
   - `ItemOut` (output): the input fields plus `id` and `created_at`

3. **Validation** (declared on the schema fields)
   - `name`: required, non-empty string, max 100 characters
   - `price`: required, number, must be greater than 0
   - `in_stock`: optional boolean (default `true`)
   - On invalid input return `400` with this exact JSON shape (add a custom `RequestValidationError` handler so it's `400`, not FastAPI's default `422`):
     ```json
     {
       "detail": [
         { "field": "price", "message": "price must be greater than 0" }
       ]
     }
     ```

4. **Error handling**
   - `GET`, `PATCH`, `DELETE` on `/items/{id}` with a missing id → `404` with `{ "detail": "Item <id> not found" }` (via `HTTPException`).
   - `POST` / `PATCH` with a bad JSON body or invalid field → `400`.
   - `DELETE` on success returns `204` with no body.

5. **Database interaction (PostgreSQL)**
   - Use **PostgreSQL**, connected via the `psycopg` (psycopg 3) driver.
   - Read the connection string from an environment variable **`DATABASE_URL`**, loaded from a `.env` file (use `python-dotenv`). Never hard-code credentials in the code.
     - Example: `DATABASE_URL=postgresql://user:password@localhost:5432/week2db`
   - Provide a **`.env.example`** file showing the variable (with placeholder values), and add `.env` to `.gitignore` so real credentials are never committed.
   - Create the `items` table on startup if it doesn't exist (`CREATE TABLE IF NOT EXISTS`).
   - Columns: `id` (`SERIAL PRIMARY KEY`), `name` (`VARCHAR(100)`), `price` (`NUMERIC`/`REAL`), `in_stock` (`BOOLEAN`), `created_at` (`TIMESTAMPTZ DEFAULT now()`).
   - Use **parameterized queries** (`%s` placeholders with psycopg) — never string-format values into SQL.

6. **README** (`fastapi-items/README.md`)
   - How to set up the database: copy `.env.example` to `.env` and set `DATABASE_URL`, and create the Postgres database.
   - How to install dependencies and run: `uvicorn main:app --reload` (port 8000), and note the docs at `/docs`.
   - The list of endpoints.
   - `curl` examples covering the full CRUD flow: create, list, get one, update (PATCH), delete, a validation error, and a 404.

7. **requirements.txt**: `fastapi`, `uvicorn`, `psycopg[binary]`, `python-dotenv`.

### How to run (after building)

```bash
cd week2/fastapi-items
python -m venv venv
source venv/Scripts/activate      # Windows Git Bash; PowerShell: venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env              # then edit .env and set your DATABASE_URL
# make sure the Postgres database exists, e.g.:  createdb week2db

uvicorn main:app --reload
```

Then open `http://localhost:8000/docs` to try the endpoints.
